落地實施指南
處方一（資安防禦）：以地端開源 YARP API Gateway 收攏無認證 C# 外掛 資安急迫性：極高

【現狀挑戰】 192.168.0.95 的 Report API 與 Local API 無驗證機制，若修改舊有的 .NET 4.8 程式碼需耗時重構與全面迴歸測試。

【處方作為】 1. 在測試機 192.168.0.23 部署開源 .NET 8 Microsoft YARP Gateway。
2. 伺服器 192.168.0.95 設定 Windows 防火牆，阻斷一般辦公網段直連，僅允許 YARP Gateway IP 訪問。
3. 由 YARP Gateway 統一掛載 JWT 驗證、API Key、來源 IP 白名單與速率限制（Rate Limiting）。
【落地成效】 零改舊程式碼、0 元軟體授權費，24 小時內達成 100% 零信任資安收攏。

處方二（營運韌性）：解耦 I05/I06 跨國專線 TDS 1433 直連與 Linked Server 韌性急迫性：高

【現狀挑戰】 總部每 30 分鐘直連越南/柬埔寨 SQL 寫庫，廠區以 Linked Server 連總部 MERGE。跨國海纜中斷或延遲飆高時，會造成資料庫長期鎖定（Locking），無法達到周副總要求的「48~72 小時斷網自律」。

【處方作為】 1. 廢止跨國資料庫直連 RPC 與 Linked Server MERGE。
2. 改採 「非同步 API 隊列 ＋ 本地端 SQLite / SQL Express 緩存」 機制。
3. 總部將工單排單異動寫入本地發布佇列；廠區 Agent 透過斷點續傳 Pull 機制抓取並落庫。
【落地成效】 斷網時廠區產線維持正常運作達 72 小時以上，專線復原後自動對齊 Reconciliation。

處方三（資料治理）：解耦 I07 程式內 23 處直接 SQL 讀取 ERP 主庫 (AXDB) 治理急迫性：中

【現狀挑戰】 研發系統與排程程式直接下 SQL 查詢 ERP 營運與財務主庫（AXDB），高頻查詢容易爭搶資源，造成鎖表風險。

【處方作為】 1. 實踐 CQRS 讀寫分離架構。
2. 透過 D365 變更追蹤（Change Tracking）將物料、顏色、客戶主檔鏡像至地端 StarRocks 高性能湖倉 或只讀複本庫。
3. 將 23 處 Direct SQL 全數遷移至只讀視圖或快取 API。
【落地成效】 消除主庫讀取鎖定，ERP 主庫負載降低 40% 以上。

處方四（制度推廣）：正式將 Duka `RD_SAMPLE` 定為全集團 Week 1 統一填報標準 管理成熟度：標竿

【現狀挑戰】 海外廠區與各部門系統眾多，缺乏統一盤點標準容易導致資訊斷層。

【處方作為】 1. PMO 以 Duka 之 RD_SAMPLE 為母版，通令越南、柬埔寨、印尼與總部所有系統窗口（MES、BPM、WMS、HRM 等）比照填報。
2. 統一交付要件：draw.io 雙頁圖、系統卡、跨系統接口清冊（I01～IN）、Windows 排程任務表。
【落地成效】 於 11/16 召開跨廠區審查會，全面建立集團統一架構資產基線。
