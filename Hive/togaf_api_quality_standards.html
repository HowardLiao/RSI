🏛️ 第一部分：TOGAF 10 企業架構（4 大支柱 ＆ ADM 循環）在信源蜂巢計畫之實施
TOGAF 10 Certified Standard

TOGAF（The Open Group Architecture Framework）是全球頂級企業架構標準。RSI Group 2027「蜂巢計畫」透過 BDAT（業務、資料、應用、技術）4 大核心架構層 與 ADM 演進循環，確保周副總戰略目標精準落實至代碼與日常維運：

TOGAF 核心架構支柱 RSI Group業務現況與痛點 (AS-IS) 2027 蜂巢計畫目標架構 (TO-BE Target Architecture)
1. 業務架構
(Business Architecture)		 • 台北總部與越/柬/印/孟各產區溝通靠電話、Email 與人工對帳。
• 產前檢查靠紙本，工單漏料或樣板未簽核仍冒險投產。
• 外點頻繁回傳資料導致白天 SD-WAN 頻寬被擠爆。 		• 4-Gate 產前門禁系統化防呆（物料100%齊套、紙樣封樣、MQP缺失結案、裁片合格，未過系統強制鎖定）。
• 外點結算一日一次原則（排定深夜 01:00~03:00 離峰打包傳輸，保護白天車間產線頻寬）。
• 業務能力地圖 (Business Capabilities) 與各廠生管/廠長 KPI 對齊。
2. 資料架構
(Data Architecture)		 • 各廠 MS SQL 資料孤島，跨廠資料難以合併。
• 白天直接對 OLTP 核心資料庫跑複雜報表，造成鎖定與死鎖。
• 歷史工單數據龐大導致資料庫磁碟爆滿。 		• Medallion 3 層現代湖倉（Bronze 原始日誌 ➔ Silver 清洗對齊 ➔ Gold 24:00 切帳總表）。
• MS SQL Server 原生 CDC 增量捕獲，零鎖表提取變更。
• 統一定義集團成衣款號、SAM 標準工時與 OEE 計算口徑。
3. 應用架構
(Application Architecture)		 • 點對點 (Point-to-Point) 雜亂呼叫，缺乏統一 API 規範。
• 遇到國際海纜切斷，車間機台立刻卡死停擺。
• 缺乏 API 契約管理，前端與後端改動經常引發相容性故障。 		• 跨國 5 層 API Platform（企業級 API Gateway 治理 ＋ JWT 鑑權 ＋ Rate Limiting 限流）。
• 海外各產區 Edge Proxy 邊緣離線自治（海纜切斷保障車間 48~72hr 連續離線生產，復網自動平帳）。
• OpenAPI (Swagger) 契約優先 (Contract-First)，消除跨團隊摩擦。
4. 技術架構
(Technology Architecture)		 • 地端依賴傳統 VPN 連線，易遭海纜波動中斷。
• 伺服器軟硬體缺乏標準化組態，單點脆弱度 (Bus Factor) 高。
• 備份缺乏不可篡改機制，存在勒索病毒風險。 		• Microsoft Solution 深化（C# .NET 8 Web API ＋ MS SQL Server AlwaysOn 高可用 ＋ Windows Server AD）。
• SASE 零信任存取 (ZTNA + CASB + DLP) 替代傳統 VPN。
• Veeam 3-2-1 備份原則 ＋ WORM 不可篡改儲存池，杜絕勒索威脅。

🧪 第二部分：企業級 API 全方位品質測試金字塔 ＆ 自動化門禁
ISO 25010 Software Quality

為徹底解決跨國製造環境中 API「改 A 壞 B」、「海外廠斷網當機」、「死鎖造成產線停滯」等品質盲點，RSI Group制定完整的 API 品質測試工程體系：

測試層級 測試目標與檢驗範疇 標準工具與技術棧 信源品質驗收標準 (Quality Gate)
1. 單元測試
(Unit Testing)		 驗證個別方法 (Methods)、業務規則驗證 (如工序計件公式、SAM 計算)。 xUnit / NUnit + Moq + FluentAssertions • 核心業務代碼行覆蓋率 (Code Coverage) >= 80%。
• 每次 Git Commit 本地秒級執行完畢。
2. 整合測試
(Integration)		 驗證 Controller ➔ Service ➔ MS SQL Server 真實資料庫讀寫與交易控制。 WebApplicationFactory (ASP.NET Core) + Testcontainers • 驗證 `SqlTransaction` 扣料與計件之 ACID 一致性。
• 杜絕多工位同時搶料產生的並發死鎖 (Deadlock)。
3. 契約測試
(Contract Testing)		 防範後端修改欄位或型別導致車間工控機前端或手持刷槍連線崩潰。 Pact (.NET) + OpenAPI Spec Diff • API 變更禁止破壞性更動 (No Breaking Changes)。
• Swagger 規格比對自動攔截缺漏欄位。
4. 功能回歸測試
(Functional API)		 端到端成衣製造場景（打樣 ➔ 4-Gate 產前門禁 ➔ 車間計件 ➔ 出貨檢驗）。 Postman Collections + Newman (CLI) • 自動化測試集合 100% 通過 (Zero Failure)。
• 自動整合至 GitHub Actions / Azure DevOps CI 流水線。
5. 效能與壓力測試
(Load & Stress)		 驗證早班打卡換款、車間數百工位同時掃描回傳時的系統極限承受力。 k6 (JavaScript 壓測) / Locust / JMeter • P95 回應時間 < 200ms，P99 < 500ms。
• 承受平日尖峰 3 倍併發請求 (500+ RPS) 無 5xx 錯誤。
6. API 資安滲透測試
(Security Testing)		 防範 OWASP API Security Top 10（SQL 注入、JWT 偽造、越權存取 BOLA）。 OWASP ZAP + SonarQube + Roslyn Analyzers • Zero Critical / High 嚴重資安漏洞。
• 強制落實參數化查詢，嚴禁字串拼接 SQL。
7. 斷網自律混沌工程
(Chaos & Resilience)		 模擬海外各產區海纜突發中斷，檢驗工廠 48~72hr 連續離線生產與復網補傳。 Pumba (Docker 故障注入) / 手動切斷網卡 • 斷網瞬間機台自動收到 HTTP 202 Accepted 暫存。
• 復網後 15 分鐘內本地暫存佇列 100% 自動平帳。
💻 第三部分：微軟 C# .NET 8 標準 API 撰寫規範、命名慣例與代碼範本
C# .NET 8 / ASP.NET Core

RSI Group內部所有軟體工程師、外部協力廠商（SI）與顧問團隊，在開發 C# .NET Web API 時，必須嚴格遵守以下企業標準：

1. RESTful URI 命名與 HTTP 動詞精確映射

• URI 規範：一律使用小寫、複數名詞，並包含清晰版本號（例：/api/v1/production-orders）。
• HTTP 動詞映射：
- GET：查詢資料（安全且冪等，禁止修改狀態）。
- POST：新增資源或觸發業務動作（例：POST /api/v1/sewing-records）。
- PUT：全量覆蓋更新資源。
- PATCH：部分欄位更新。
- DELETE：軟刪除（標記 IsDeleted = 1，禁止物理刪除成衣生產紀錄）。

2. 統一 API 回傳信封格式 (Standard API Envelope Model)

所有 API 無論成功或失敗，回傳之 JSON 必須封裝於標準結構中，方便前端與車間工控機統一解析：

public class ApiResponse<T> { public bool Success { get; set; } // true / false public string Code { get; set; } = "RSI-200"; // 集團標準業務代碼 public string Message { get; set; } // 繁中清晰提示訊息 public T? Data { get; set; } // 業務實體資料 public string TraceId { get; set; } // 鏈路追蹤 ID (用於日誌排錯) public DateTime Timestamp { get; set; } = DateTime.UtcNow; public static ApiResponse<T> Ok(T data, string msg = "操作成功") => new() { Success = true, Code = "RSI-200", Data = data, Message = msg }; public static ApiResponse<T> Fail(string code, string msg) => new() { Success = false, Code = code, Message = msg }; }

3. C# .NET 8 標準 Controller 企業骨架範本 (含 4-Gate 門禁檢核與交易控制)

[ApiController] [Route("api/v1/[controller]")] [Authorize] // 強制 JWT 身分驗證 [Produces("application/json")] public class ProductionOrdersController : ControllerBase { private readonly IOrderService _orderService; private readonly ILogger<ProductionOrdersController> _logger; public ProductionOrdersController(IOrderService orderService, ILogger<ProductionOrdersController> logger) { _orderService = orderService; _logger = logger; } /// <summary> /// 車間工單投產門禁審查 (4-Gate 產前門禁防呆 API) /// </summary> [HttpPost("{orderId}/start-production")] [ProducesResponseType(typeof(ApiResponse<ProductionTicketDto>), StatusCodes.Status200OK)] [ProducesResponseType(typeof(ApiResponse<GateCheckResultDto>), StatusCodes.Status409Conflict)] public async Task<IActionResult> StartProduction(string orderId, [FromBody] StartOrderCommand cmd) { // 1. 執行 4-Gate 產前門禁防呆審查 (物料齊套/紙樣封樣/MQP改善/裁片封包) var gateResult = await _orderService.VerifyFourGatesAsync(orderId); if (!gateResult.Passed) { _logger.LogWarning("工單 {OrderId} 4-Gate 產前門禁未通過: {Reason}", orderId, gateResult.FailureReason); return Conflict(ApiResponse<GateCheckResultDto>.Fail("RSI-409-GATE", gateResult.FailureReason)); } // 2. 開啟資料庫交易 (SqlTransaction 保障 ACID 一致性) var ticket = await _orderService.DispatchOrderWithTransactionAsync(orderId, cmd); return Ok(ApiResponse<ProductionTicketDto>.Ok(ticket, "4-Gate 審查通過，工單已成功投產！")); } }

DevOps & Automation

全集團推行標準化工具鏈，消除開發人員各自為政之現象：

工程階段 推薦標準工具 (Recommended Tools) 工具實務職能與自動化落地方式

• 嚴格規範輸入參數格式、必填欄位與範例回傳值。
