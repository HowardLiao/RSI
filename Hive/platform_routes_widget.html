🏆 路線 1：Microsoft Azure 原生組合 (APIM ＋ ADF ＋ ADLS Gen2)

• 優勢：D365 F&O (C++) 唯一官方原生 Synapse Link 入湖；地端 MS SQL 經 ADF SHIR 安全穿透內網；全微軟技術棧內部接手最容易；微軟金級 SI 合作夥伴極為充足。
• 風險防禦：規避微軟 2026-11-30 Export to Data Lake 永久終止之重大生命週期風險；以 Delta Lake 開放格式存於 ADLS，保有未來跨雲資料自主性。

🔴 路線 2：Google Cloud Platform 受管組合 (Apigee ＋ Datastream ＋ BigQuery)

• 優勢：BigQuery SQL 分析性能與無伺服器擴展性極佳；Datastream 原生支援地端 MS SQL 日誌捕獲。
• 挑戰：D365 SaaS 無法直連 GCP，需於 Azure 落地再跨雲搬遷；內部 IT 需重新學習 GCP IAM 權限與 BigQuery 方言。

🟠 路線 3：Amazon Web Services 受管組合 (API GW ＋ DMS ＋ S3 / Redshift)

• 優勢：全球機房與 CDN 覆蓋最完整，微服務配套最成熟。
• 挑戰：組件顆粒度過碎（API GW + Step Functions + DMS + S3 + Glue + Redshift），跨服務權限與觀測鏈條繁雜；DMS 需經 S3 暫存批次套用延遲較高。

🟢 路線 4：Open Source 開源自建組合 (APISIX ＋ Debezium ＋ MinIO / Iceberg)

• 優勢：軟體零授權費、資料 100% 留存在地端機房；海外各廠邊緣採用 Envoy Proxy ＋ SQLite 能以極致輕量實現 48~72hr 斷網自律生產！
• 致命短板：D365 封閉 SaaS 無法直連；總部自建 K8s/Kafka 需長期供養高階 SRE，一旦核心離職形成嚴重單點黑數（Bus Factor=1）。

⚠️ 特例剖析：為什麼第一階段不宜採購 MuleSoft Anypoint？

• 定位錯誤：MuleSoft 是 iPaaS 業務交易整合平台，不是「巨量資料分析與 Lakehouse」；它無法取代 CDC 日誌擷取、ADLS 湖倉與 BI 報表。
• 授權極度昂貴：按 Core/vCore 計價，三年 TCO 數千萬元；在需求未成熟前採購會造成巨大資本浪費。第一階段先以受管輕量 APIM 滿足需求即可。
