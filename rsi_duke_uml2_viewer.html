Duke 交付之關鍵架構與介面規範總成 (作為 UML 2 圖資之唯一標準)

1. D365 C# 服務體系

  • D365 C# 外掛 API: 運行於 192.168.0.95 (.NET 4.8 / Web API 2)，包含 Report API (:8085 正式/:8082 UAT) 與 Local API (:80 正式/:8081 UAT)。
  • 全無驗證風險: 外掛 API 完全無 Token/身份驗證，僅需提供參數即可下載 PDF/Excel，須透過 API Gateway 收攏。
  • D365 C# 80 Operations: 涵蓋 JCOM_WebServices、RSI_WebServices 等 31 個服務，採 Entra ID Bearer Token 授權，回傳統一結構 RSI_RT<T>。

2. CQS 品質微服務 (.NET 8 ARR)

  • 架構演進: CQS 採用最新 .NET 8 框架，正處於現代化過渡期。
  • IIS ARR 轉發: 正式機 192.168.0.22:8011，測試機 192.168.0.23:8011，由 IIS Application Request Routing (ARR) 在 Port 8012 進行反向代理。
  • 平替方案: 建議以開源 YARP / Envoy 替換 Windows ARR，解除微軟專屬授權綁定。

3. RD_SAMPLE 示範範本核心問題

  • 1,490 處直接下 SQL: 自寫 ADO.NET 直下 SQL 語句，連線字串內含明碼 sa 帳號，缺乏 ORM 與參數化防護。
  • 跨庫查詢 AXDB (23 處): 直連 rsiaxdb1 營運主庫，引發鎖表與效能爭用。
  • 13 項 Windows 排程依賴: 包含每 5 分鐘通知輪詢、每 30 分鐘跨國專線 TDS 直寫 (Sync_RSV/RSG) 及每日 23:01 批次主檔同步。

4. 四大處方與 48~72 小時在地自律

  • 處方 1: 導入 YARP API Gateway 收攏無驗證外掛與 C# 80 Operations。
  • 處方 2: 跨國資料庫直連改為 RabbitMQ 斷網自律離線訊息佇列。
  • 處方 3: ADO.NET 重構為 Dapper + 預行編譯 SQL，拔除明碼 sa 帳號。
  • 處方 4: Windows Task Scheduler 遷移至 Hangfire / KEDA 在地容器化排程。
